# متجر نقاط جامع قباء 🕌

نظام مكافآت لطلاب معهد تحفيظ القرآن: الطلاب يجمعون نقاطاً (حفظ، مراجعة، صلاة جماعة…) يمنحها المشرف يدوياً،
والأدمن يفتح المتجر عند الحاجة فيطلب الطلاب جوائزهم بنقاطهم، ويحصل الأدمن على تقرير طلبات كامل بأسماء أصحابها.

بُني بـ **Next.js 14 + Supabase (PostgreSQL + Storage) + Tailwind**، بواجهة عربية RTL متجاوبة مع الجوال والتابلت والحاسوب.

---

## المزايا
- تسجيل دخول باسم مستخدم + كلمة سر (بدون إيميل)، بجلسة JWT آمنة.
- **مفتاح المتجر**: زر مفتوح/مغلق واحد في ترويسة لوحة الأدمن — بتأكيد قبل الإغلاق. عندما يكون مغلقاً يرى الطالب رسالة "المتجر مغلق حالياً" بدل المتجر.
- **إدارة الحسابات**: شاشة مركزية واحدة تعرض كل حلقة وطلابها، مع تعديل رصيد كل طالب مباشرة (رقم يدوي من الأدمن)، وإنشاء حلقة جديدة + حسابات طلابها دفعة واحدة (بيانات دخول قابلة للطباعة)، وإضافة طلاب لاحقاً لحلقة موجودة، وتعديل/حذف الحلقات والطلاب (الحذف نهائي ويشمل طلباتهم).
- **المنتجات**: رفع صورة المنتج بالسحب والإفلات (أو بالنقر لاختيار ملف) مباشرة إلى Supabase Storage.
- **تقرير الطلبات**: مقسّم حسب كل حلقة ثم كل طالب (مشترياته ورصيده المتبقي)، وفي النهاية إجمالي كل منتج على مستوى المتجر بالكامل (للتحضير)، مع طباعة وتصدير CSV.
- منطق الشراء **atomic** داخل قاعدة البيانات (يمنع الرصيد السالب وبيع مخزون غير موجود عند الطلبات المتزامنة).

## خطوات التشغيل

### 1) أنشئ مشروع Supabase
من supabase.com، ثم من **SQL Editor**:
- **مشروع جديد بلا بيانات:** الصق القسم الأول من `supabase/schema.sql` (قبل تعليق `MIGRATION`) وشغّله.
- **مشروع قائم بالفعل** (فيه حلقات/طلاب/منتجات حقيقية من نسخة سابقة تحتوي جولات ونقاط): شغّل بدلاً منه قسم **MIGRATION** في نهاية نفس الملف (احذف علامتي `/*` و `*/` المحيطتين به أولاً). هذا القسم يحافظ على كل الطلاب والحلقات والمنتجات وسجل الطلبات، ويحذف فقط الجولات وسجل النقاط القديمين.
- **قاعدة تعمل بالفعل بهذا النظام** (بدون جولات/نقاط، لكن بدون خانة كلمة السر الظاهرة) وتحتاج فقط تحديث كلمة السر القابلة للعرض: شغّل هذا السطر فقط:
  ```sql
  alter table students add column if not exists password_plain text;
  ```
  ملاحظة: الطلاب الذين أُنشئوا قبل هذا التحديث ستظهر خانة كلمة سرهم فارغة (—) في إدارة الحسابات لأن كلمة سرهم الأصلية لم تُخزَّن بنص واضح؛ يمكن للأدمن تعديل بياناتهم أو حذفهم وإعادة إنشائهم إن احتاج الأمر لاسترجاع كلمة سر ظاهرة.

هذا ينشئ أيضاً مخزن صور المنتجات في Supabase Storage تلقائياً (`product-images`, عام/public). إن لم ينجح إنشاؤه بالسطر SQL لسبب ما، أنشئه يدوياً من **Storage** في لوحة Supabase: New bucket → الاسم `product-images` → فعّل **Public bucket**.

### 2) الإعدادات
انسخ `.env.example` إلى `.env` واملأ القيم:
```
NEXT_PUBLIC_SUPABASE_URL   = من Project Settings > API
SUPABASE_SERVICE_ROLE_KEY  = من Project Settings > API (المفتاح السرّي — لا تنشره)
AUTH_SECRET                = أي نص عشوائي طويل
```

### 3) التنصيب والتشغيل
```bash
npm install
node scripts/seed-admin.mjs "المشرف" admin ضع_كلمة_سر_قوية   # ينشئ أول حساب أدمن
npm run dev
```
افتح http://localhost:3000 وسجّل الدخول بحساب الأدمن.

### 4) النشر
انشر على **Vercel** (اربط المستودع + أضف نفس متغيّرات `.env`). أمر البناء الافتراضي يعمل مباشرة.

## سير العمل
1. الأدمن يفتح **إدارة الحسابات** وينشئ حلقة + حسابات طلابها دفعة واحدة (يطبع بيانات الدخول ويوزّعها)، أو يضيف طلاباً لاحقاً لحلقة موجودة.
2. الأدمن يضيف المنتجات وأسعارها وكمياتها وصورها (سحب وإفلات).
3. مع تقدّم الطلاب (حفظ، مراجعة، صلاة جماعة…) يكتب المشرف الأرقام للأدمن، فيدخل الأدمن رصيد كل طالب يدوياً من نفس شاشة إدارة الحسابات.
4. عند اقتراب موعد الطلب: الأدمن يفتح **المتجر** بالزر الموجود في ترويسة لوحة التحكم.
5. يطلب الطلاب جوائزهم طالما المتجر مفتوح.
6. الأدمن يغلق المتجر (بتأكيد)، ثم يفتح **تقرير الطلبات** ويطبعه/يصدّره — مقسّم حسب الحلقة ثم الطالب، وفي الأسفل إجمالي كل منتج للتحضير.

## الهوية البصرية
الواجهة ملتزمة بالهوية الرسمية لجامع قباء:
- **الخط**: خط "ثمانية" الرسمي (Sans للنصوص، Serif Display للعناوين البارزة)، محمّل محلياً عبر `next/font/local` من `public/fonts/`.
- **الشعار**: العلامة الرسمية (أيقونة المحراب) في `public/brand/` بثلاث نسخ لونية (Red / Black / White) وأشكال (أيقونة، أفقي، رئيسي)، مستخدمة في الترويسات وصفحة الدخول وأيقونة المتصفح.
- **الألوان**: مطابقة تماماً لملف الألوان الرسمي (`.ase`) ومضبوطة في `tailwind.config.ts` (الأحمر `#9A1B1F`، كريمي `#ECE8DF`، ذهبي `#C69A5D`، وبقية الدرجات في `brand.*`).

## ملاحظات أمنية
- كل الوصول لقاعدة البيانات ولمخزن الصور يتم من السيرفر بمفتاح service role؛ لا يصل المتصفح للمفتاح إطلاقاً.
- تسجيل دخول الطالب يعتمد فقط على `password_hash` المشفّر (bcrypt). عمود `password_plain` نسخة نصية إضافية **مقصودة** ليتمكّن الأدمن من عرضها وتوزيعها على الطلاب (حسابات بسيطة بلا بريد إلكتروني لاسترجاعها)؛ لا يُستخدم إطلاقاً في التحقق من الدخول.
- لإلغاء طلب (إرجاع النقاط والمخزون)، استعمل الدالة `cancel_order` في قاعدة البيانات.
- **حذف حلقة أو طالب نهائي ومباشر** (Cascade) من شاشة إدارة الحسابات: يحذف الطالب كل طلباته، ويحذف الحلقة كل طلابها وطلباتهم. لا يوجد تراجع بعد الحذف.
